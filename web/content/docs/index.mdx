This is a practice book. Every chapter is a study: a technique is named, a drill is
worked, and the result is marked. You will not finish a study by reading it. You finish
it by running it.

Keep three things open: this book, your editor, and a terminal. Every line of terminal
output printed here is real output from the code in this repository, and every code
sample is pulled from a package that `dart analyze` and `dart test` run against. If a
sample is in this book, it compiles.

## What you need

Dart 3.13 or later. Check what you have:

```bash
dart --version
```

Nothing else. No account, no editor plugin, no framework.

## How a study is laid out

The number and title sit at the top, and under them a line in italic tells you how to
play this one. Then come the drills, each bracketed by a repeat sign and numbered like
fingering above a note. A held mark in the margin means stop and read.

At the end of each study you mark it worked, and the mark stays.

## What this book does not cover

Flutter. It is a large enough subject to deserve its own book, and mixing it in here
would make both worse. This book takes you to the point where Flutter makes sense.

## Where this comes from

The format is borrowed, with thanks, from Chris James' *Learn Go with Tests*. The
difference here is deliberate: that book leads with the test, this one explains the idea
first and then uses a test to prove and sharpen it. The goal is not test-driven
development as a discipline you perform. It is a way of checking that you understood.
